2.3 Evictor — resolve the Incompatible state first
Deployment mode: self-managed (status: Incompatible, allowed: false, enabled: true) → CAST-managed (helm upgrade … --set autoscaler.castai-evictor.managedByCASTAI=true) Restores continuous bin-packing — today only the hourly-nightly scheduled rebalancings compact, and they now converge (runs skip with achievedSavingsBelowThreshold). All evictor tunables below become console-editable. Live state identical on all 3 NGM clusters: {enabled: true, allowed: false, status: "Incompatible"} = CAST AI detected a self-managed Evictor; no evictor setting is changeable from the console until ownership is decided. Alternative: keep self-managed and set the same values as Helm values.
cycleInterval: "1m" → "10m"; maxTargetNodesPerCycle: 20 (default) → 5 Sized to the observed 30-day peak of 574 nodes: stops overlapping 1-minute cycles cancelling drains mid-flight; caps kube-apiserver eviction pressure per cycle. CAST AI docs sizing table: 500+ nodes → 10m interval, 5 targets/cycle. Helios peak (574) is in that band.
aggressiveMode: false · scopedMode: false · ignorePodDisruptionBudgets: false · softTainting: false (keep all); nodeGracePeriodMinutes: 10 (keep); dryRun: false (keep) Production stays conservative: Evictor always respects PDBs; no forced eviction of single-replica or unprotected pods; grace period matches JVM/slow-start workloads. Aggressive/scoped modes add nothing here (~95% of nodes already CAST-managed); ignorePodDisruptionBudgets: true must never be set on production.
Pre-flight (prerequisite, not a field): kubectl get pdb -A audit + review the 2 autoscaling.cast.ai/removal-disabled pins Prevents stalled drains: PDBs with minAvailable == replicas block every eviction; the 2 pinned nodes (was 8 on 2026-10-02 — improving) freeze one instance each and will not roll in rebalances. Audit evidence: removal-disabled pins helios 2 live now; zero-disruption PDBs are the standard cause of "evictor does nothing" reports.
2.4 Rebalancing — keep the schedule, make it gentler
evictGracefully: → true on the hourly-nightly plan; executionConditions.achievedSavingsPercentage: 5 (keep — do not lower on helios); minNodes: 1, nodeTtlSeconds: 300, numTargetedNodes: 50 (keep) Drained-but-blocked nodes get cordoned and retried the next night instead of force-drained at drainTimeoutSec — gentler on production. Keeping the 5% floor avoids micro-thrash; the window (22:00–03:59 Europe/London, 50 nodes/run, UtilizedPrice) already works. Live jobs show recent "skipped"/"failed" runs = achievedSavingsBelowThreshold — a benign signal: the on-demand curve has converged, so instance-to-instance reshuffling is nearly exhausted. New headroom comes from the mode changes in 2.5–2.7, then full rebalances re-open savings.

5. Rollout order & known blockers

5.1 Rollout order

  1. P0 — maxPods fix (this cluster last within the fleet): apply the §4 node configuration change to ngm-integ-eks first, then ngm-kronos-eks, then ngm-helios-eks — one rebalance cycle apart. Fixes the live 29-vs-55 mismatch on the 8 r6a.large nodes; zero cost risk.
  2. P1 — prerequisites: run the PDB audit and decide evictor ownership (CAST-managed recommended). Validate FAMILY_AL2023 + the custom initScript on integ; create the eu-central-1c /18 subnet and add it to the node configuration subnet list. The shared spot pilot runs on integ's dedicated tainted template — not here.
  3. P2 — helios template changes: apply §3 (maxCpu 24, minCpu 4, 3 AZs, c5a/c5ad exclusion, family priorities, CPU limit 6000) after ~1 week of integ data; roll the fleet via the nightly rebalancing windows. Raise maxCpu 24 → 32 later if PDB/eviction behavior stays clean.
  4. P3 — structural follow-ups: WOOP enablement/offender fixes (2.7), SP/RI import (2.8), namespace-gated spot pilot only after all preconditions in 2.5 hold. Hibernation: never (production).
