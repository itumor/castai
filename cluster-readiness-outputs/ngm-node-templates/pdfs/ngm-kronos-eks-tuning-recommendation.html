2. Recommendations — every change, one row

All settings changes apply to newly provisioned nodes only; the existing ami-update-weekly / nightly rebalancing windows roll the fleet without touching running workloads. Estimated-savings ceilings below are CAST AI scenario estimates on listing-price basis; the hibernation figure is computed from observed node-hours.

2.2 Node configuration — ngm-kronos-castai (v31)
kubeletConfig.maxPods: 55 → removedeks.maxPodsPerNodeFormula: unset → math.least(NUM_MAX_NET_INTERFACES * (NUM_IP_PER_INTERFACE - 1) + 2, 110) Eliminates the 29-vs-55 scheduling lie on r6a.large entirely; lets 4xlarge nodes use their real 234-pod ceiling (~8× above your observed ~14 pods/node density, capped at 110 for stability). CAST AI docs explicitly recommend no static maxPods with the AWS VPC CNI ("the same node configuration is usually used for different instance types"). KEN formula: ENIs × (IPs/ENI − 1) + 2. Subnet sharing with integ is fine: <1% of 65.5k IPs used.
image: ami-0706179e8561145ae (pinned) → "" + eks.imageFamily: FAMILY_AL2023 AMI auto-tracks k8s version + security patches; kubeReserved/evictionHard (ignored on AL2 per docs) start actually applying; unlocks Container Live Migration later. The pinned AMI ages with manual drift. Validate on integ first — your custom initScript must be AL2023-safe.
diskCpuRatio: 0 → 1; minDiskSize: 100 → 50 GiB Root disks scale with node size (16 vCPU → 64 GiB) instead of a flat 100 GiB; small monthly saving, large-node sizing unchanged. Helios math: 300 × 100 GiB gp3 ≈ $2.4k/mo of mostly-idle roots; same flat pattern on kronos's 14 nodes.
imdsV1: unset → false (IMDSv2-only); drainTimeoutSec: unset → 1200; volumeType: gp3 (keep) Consistent hardening; rebalancing drains become deterministic (20 min) instead of the hidden default. Audit noted IMDSv2 already intended; explicit drain timeout matters once hibernation + rebalances drive more node churn.
kubeReserved 1000m/4000Mi/5Gi + systemReserved + evictionHard: keep as-is No change — the relative tax halves automatically once maxCpu grows. The reservation is per-node overhead; amortizing it is the maxCpu lever's job.
2.3 Evictor — decide ownership first
Self-managed install (status: Incompatible, allowed=false) → CAST-managed: helm upgrade castai castai-helm/castai -n castai-agent --reset-then-reuse-values --set autoscaler.castai-evictor.managedByCASTAI=true Unlocks continuous bin-packing between rebalances; all settings become console-editable. "Incompatible" = CAST AI detected a self-managed Evictor; today only the scheduled rebalancings compact the cluster. Option B: keep self-managed and set the same values as Helm values.
cycleInterval: 1m → KEEP 1m; maxTargetNodesPerCycle: 20 (default) → KEEP 20; aggressiveMode / scopedMode / softTainting: all stay false; nodeGracePeriodMinutes: 10 (keep); ignorePodDisruptionBudgets: false (never true on anything shared) Zero change needed for kronos's size — small cluster, fast cycles are safe. Docs sizing table reserves 10m / 5-per-cycle for 500+ node peaks (helios 574, integ 885); kronos peaked at 104 nodes in 30d. Pre-flight: kubectl get pdb -A — fix PDBs where minAvailable == replicas; review the 1 removal-disabled pin.
2.4 Rebalancing — keep schedules, lower the bar
executionConditions.achievedSavingsPercentage: 5 → 2% on kronos plans (prescale / postscale / hourly / ami-update-weekly all stay enabled) Micro-wins (single-node swaps) stop being skipped; zero risk of thrash — the algorithm still only acts above the floor. Every recent kronos skip resolves to achievedSavingsBelowThreshold — benign: the on-demand curve has converged. A 2% floor keeps small savings flowing; expect skips to continue once converged again. After WOOP/spot changes land, rerun a full-cluster rebalance — the curve reopens.
2.5 Hibernation pilot — NEW (kronos is the one candidate)
NEW weekend hibernation schedule: pauseConfig.cron: "0 20 * * FRI" + resumeConfig.cron: "0 7 * * MON", timezone Europe/Berlin Resume jobConfig.nodeConfig: { "instanceType": "m6a.xlarge", "spotConfig": { "spot": false }, "zone": "eu-central-1a" } ≈ 59 h/wk off ≈ 35% of kronos compute ≈ ~$0.7k/mo saved. PVs keep billing during hibernation (storage unaffected — compute only). The weekend collapse is already observed behavior: 3 nodes / ~14 vCPU live on Sunday 2026-10-04; node count floor of 3 across the 30d window. Hibernation formalizes what usage already does. Confirm weekend idleness with the kronos team before enabling.
2.6 Spot — Phase 2 (after integ pilot proves itself)
Default template spot: false → true with onDemand: true, useSpotFallbacks: true, fallbackRestoreRateSeconds: 300, enableSpotReliability: true (+20% price limit), spotInterruptionPredictionsType: "castai-predictions", shouldTaint: false (dev cluster — wide tolerance, no opt-in needed) CAST AI scenario ceilings (listing basis): SpotInstances −68.5%, SpotOnly −84% of $2.3k/mo ≈ up to ~$1.9k/mo. Guards: on-demand fallback on, reliability ML, node-count swings absorbed by fallbacks. Spot is 0% org-wide today; kronos is the cheapest possible place to go second (small blast radius, bursty 3→104 profile is exactly what spot discounts). Run only after the integ spot-batch template pilot reports clean. Housekeeping regardless: replace deprecated aws-rebalance-recommendations prediction type on all templates.
⚠ Hibernation prerequisites — kronos pilot (verify all before enabling)
  1. EKS hibernation IAM permissions. These clusters were onboarded 2025-09-30 → the pre-October-2025 rule applies: re-run the Phase-2 onboarding script or re-apply with Terraform provider ≥ v7.74.0 so the hibernation permissions land on the role.
  2. aws-auth ConfigMap check. If the node IAM role authenticates via aws-auth (aws eks describe-cluster --query 'cluster.accessConfig.authenticationMode'): set eks.nodeGroupArn on the default node configuration to a dedicated resume role — otherwise deletion of the resume node-group removes the role from aws-auth and breaks the remaining cluster.
  3. CriticalAddonsOnly tolerations on all critical components (CNI, DNS, castai-agent, cluster-controller, pod-mutator, workload-autoscaler) — check chart/app versions against the docs minimums; cast agent v0.161.1 already exceeds the required minimum. Verify charts with helm list -n castai-agent.
  4. Webhook deadlock. If Gatekeeper or Kyverno (or similar policy engines) are present, read the CAST AI docs' webhook-deadlock section — a policy webhook that sleeps with the cluster can block resume.
  5. Billing note. Persistent volumes keep accruing charges throughout hibernation; only compute pauses. Node-count ceiling (~1000) is not a concern at kronos's scale.

Known blockers (expected — not failures)

  • 1 removal-disabled node on kronos will not roll during rebalances — review the pin deliberately; plans correctly skip it.
  • Shared subnets with integ (subnet-0a1fe78d4bc69f2ac / subnet-0dacd9b4f9407e0ab): coordinate any subnet/AZ and CIDR additions across both clusters in one plan.
  • Evictor self-managed / Incompatible until the ownership decision — continuous bin-packing stays off; schedule-based rebalancing is the interim path.
  • Rebalancing skips achievedSavingsBelowThreshold are benign and will continue on the converged on-demand curve; the 2% floor + hibernation + spot are what reopen headroom.
  • Weekend idleness is inferred, not confirmed with the team — the one human gate before the hibernation schedule goes live.
  • Persistent volumes keep billing during hibernation; kronos's storage line is small and untouched by this plan.
