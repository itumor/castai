Hi all,

As you know we have Azure AKS issues where castctl is trying to create a new Entra Application. Creation of Entra Apps is not allowed at Siemens in this manner.
The Entra Application must be pre-created via our internal Self Service first.

Proposed Workflows

SIEMENS - Prerequisite for Azure based Clusters :

Azure Subscription, where AKS lives, owners create a new Entra Application via our Self-Service Portal. 
The new create Entra App is given the Contributor role or Kubernetes roles on the Azure subscription 
Client Secret is created in Entra for the newly created Enter App. 
The Entra App will have a Client Id (sometimes referred to as App Id ) and Client Secret. 

Cast CTL

User runs castctl to install read only/auto scale modes 
Castctl must have a flag to use the above client id & client secret when onboarding an AKS Azure cluster. 
Owners can onboard easily 

Helm
The helm chart must allow users to set a Entra Client Id & Secret and to not create one. 

Terraform
    The recommended way at Siemens. To use Terraform/Open Tofu where possible. Since Terraform uses CICD pipelines the Entra App should already be in use by teams.



The response from support is wrong:
We confirmed that you can pre-create the App Registration and have castctl reuse it, as long as it uses the exact name that castctl expects.
 
The naming needs to be:
CastAKSRole-<first 8 characters of cluster ID>
CAST.AI <cluster-name>-<first 8 characters of cluster ID>
You should never use name based checking as names can be updated or changed by admins or other systems at use, especially at places like Siemens.
