Meeting Minutes
Meeting: CAST AI 1 to 1 | Siemens Dev (DI FA vLab) - Follow Up Session #2
Date/Time: 05 Oct 2026, 09:30 AM
Attendees: Yang, Fan, Ebrahim Ramadan, Vijay Kumar, Paras Puri (ext.)

Objective
Troubleshoot the CAST AI onboarding and node autoscaling setup for the Siemens Dev (DI FA vLab) EKS cluster, focusing on IAM permission issues preventing successful installation.

Key Discussion Points

1. Review of Installation Failure
The team reviewed errors encountered during CAST AI onboarding.
The primary issue identified was that the AWS role used for the installation process could not create IAM roles due to an explicit deny enforced by the organization's permissions boundary policy.
Additional permission validation showed that sts:GetCallerIdentity was initially not permitted for the execution role, which contributed to onboarding validation failures.

2. IAM Role and Permission Investigation
Participants examined the IAM roles attached to the EKS environment and reviewed the associated permission boundaries.
It was confirmed that the environment allows role creation only when required permission boundaries are attached.
The team validated that the onboarding process was attempting to create new IAM roles automatically, which conflicted with existing corporate security restrictions.

3. Troubleshooting Activities
CAST AI support requested: Full error details. Execution of identity verification commands. Collection and sharing of support bundle logs.
The team generated and reviewed support bundle outputs for further analysis.
A policy update was tested to allow identity verification checks and additional validation commands were run to confirm permissions.

4. Root Cause Assessment
Even after resolving the identity-check permission issue, onboarding continued to fail when CAST AI attempted to create IAM roles required for node autoscaling.
The team concluded that the main blocker is the inability of the installation process to create IAM roles because of explicit restrictions defined by the permission boundary.

5. Alternative Deployment Approach
CAST AI proposed using Terraform-based deployment modules as an alternative onboarding method.
Two Terraform modules were discussed: IAM role creation module. CAST AI EKS cluster integration module.
Another option considered was manually creating the required IAM roles and supplying them as inputs during onboarding to avoid automatic role creation.

Decisions
The current installation method cannot proceed due to IAM role creation restrictions.
Terraform-based deployment is the most viable workaround currently identified.
The Siemens team will evaluate whether the required IAM roles can be created manually and integrated into their existing Terraform setup.
