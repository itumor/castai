## Findings (labelled)

**Docs-verified** (fetched live this session, pages updatedAt 2026-09-17…2026-09-25):

- CAST AI has **no native email notification channel**. FAQ: "Currently, we only support notifications via the CAST AI console as a webhook for PagerDuty and Slack." (docs.cast.ai/docs/logs-alerts-and-metrics)
- Delivery methods = native Slack integration + **custom Webhook** with fully customizable request template (Go templating; variables `.Message`, `.Cluster.Name`, `.NotificationID`, `.Severity`, `toISO8601 .Timestamp`, `toJSON .Details`, `toEscapedString .Details`). Ready-made templates: PagerDuty, OpsGenie, MS Teams (Incoming Webhook + Workflows), incident.io, Slack cost anomalies. (docs.cast.ai/docs/setup-notification-webhook, docs.cast.ai/docs/examples)
- Console path: Notifications icon → View all → Manage alerts → Create alert → Webhook. Category **All** captures every category in one selection; one alert configuration targets one category (per July 2026 changelog).
- String-typed fields must render strings: `description: {{ toJSON .Details }}` is rejected with `422 validation_error`; use `{{ toEscapedString .Details }}`. Header `Content-Type: application/json` required.
- Docs explicitly recommend validating the downstream endpoint by POSTing a sample payload with `curl` before/after wiring CAST AI (OpsGenie example).
- MS Teams example page contains a **Test Notification** section under the Incoming Webhook method (screenshots; likely a console feature — verify in their console version).
- Every delivered notification also appears in the console's Notifications panel (top navigation) — free in-product cross-check.
- Changelogs June+July 2026 confirm Slack + webhook remain the channels; July 2026 added a dedicated Workload Autoscaler notification category; June/July record notification-config operations in the org Event Log. **No email feature announced.**
